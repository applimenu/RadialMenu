# GitHub, установщик и обновления RadialMenu

## Создание репозитория

1. Войди в GitHub. В Visual Studio открой решение из папки RadialMenu1 и выбери **Git → Создать репозиторий Git → GitHub**.
2. Выбери свой аккаунт, укажи имя RadialMenu и видимость Public. Проверь локальный путь. В новый репозиторий должна попасть папка проекта RadialMenu1 с RadialMenu1.csproj, installer и relay.
3. Нажми **Создать и отправить**. Проверь на GitHub, что в репозитории видны исходники. Файлы bin, obj, .vs, параметры пользователя и секреты исключены через .gitignore.

Альтернативный путь через сайт — создай пустой Public-репозиторий на https://github.com/new, затем выполни в папке проекта команды из блока GitHub «…or push an existing repository from the command line». Для отправки потребуется авторизация GitHub в Git Credential Manager. Если сначала создаёшь локальный репозиторий вручную, выполни git init -b main, git add . и git commit перед командами remote и push.

## Что делает Inno Setup

dotnet publish собирает папку программы. При автономной публикации в ней уже есть .NET Desktop Runtime. Inno Setup берёт эту папку, сжимает её в один RadialMenu-Setup-win-x64.exe, создаёт ярлык в «Пуск» и регистрирует удаление в Windows. Компилятор ISCC.exe нужен на компьютере разработчика. Пользователь скачивает готовый установщик и проходит обычный мастер. RadialMenu устанавливается в профиль пользователя, поэтому стандартная установка не требует прав администратора.

Портативную публикацию можно запустить без мастера. Для этого нужно целиком распаковать ZIP и открыть RadialMenu1.exe в распакованной папке.

## Первый релиз и следующие обновления

1. Установи Inno Setup 6.3 или новее на компьютере разработчика.
2. Запусти PowerShell из папки проекта. Замени OWNER/REPO на имя своего репозитория и укажи версию.

       .\installer\Build-Release.ps1 -Repository 'OWNER/REPO' -Version '1.0.0'

3. Готовый файл installer\out\RadialMenu-Setup-win-x64.exe можно открыть на своём компьютере и отправить другу. Если нужно хранить разные версии рядом, укажи папку для каждой версии.

       .\installer\Build-Release.ps1 -Repository 'OWNER/REPO' -Version '1.1.0' -OutputDirectory '.\installer\out\v1.1.0'

4. Для публикации создай GitHub Release с тегом, соответствующим версии сборки, и прикрепи готовый EXE. Опубликуй как стабильный релиз. Черновики и предварительные выпуски можно оставить для тестирования.
5. Следующие версии собирай с увеличенным номером и публикуй под соответствующим тегом. Имя установщика остаётся прежним.

Для ARM64 используй параметр -Architecture arm64 и прикрепи RadialMenu-Setup-win-arm64.exe. GitHub вычисляет контрольную сумму загруженного файла. RadialMenu проверяет её перед запуском установщика.

В интерфейсе GitHub шаг публикации находится в **Releases → Draft a new release**. Создай тег той же версии, что передана в Build-Release.ps1, добавь заметки о версии, прикрепи готовый EXE и опубликуй. Черновик можно использовать для проверки вложений. Предварительная версия с отметкой Pre-release не будет предложена пользователям стабильной сборки.

Пользователи первый раз скачивают установщик со страницы Releases. Дальше они открывают **Приложение → Проверить обновления**. Если выйдет более новая стабильная версия, можно отдельно нажать «Установить». Перед стабильной публикацией проверь чистую установку и обновление поверх предыдущей версии на другом профиле Windows или виртуальной машине.

## Отчёты об ошибках через Telegram

Пользователь открывает форму, пишет об ошибке или идее и нажимает **Отправить**. В Telegram приходят текст и версия RadialMenu. Форма закрывается после подтверждения доставки. При сбое сообщение остаётся в форме для повторной отправки.

### Развёртывание с Cloudflare Workers

1. Создай бота через [@BotFather](https://t.me/BotFather) командой `/newbot`. Открой личный чат с этим ботом и нажми **Старт**.
2. Получи числовой `message.chat.id` вызовом [Telegram Bot API getUpdates](https://core.telegram.org/bots/api#getupdates) для своего бота. Токен вводи только в локальном терминале или прямо в секретах хостинга.
3. Открой терминал в папке `relay/cloudflare` и разверни Worker. Нужны Node.js и Wrangler 4.36.0 или новее. При первом развёртывании Wrangler предложит войти в Cloudflare.

       npx wrangler deploy
       npx wrangler secret put TELEGRAM_BOT_TOKEN
       npx wrangler secret put TELEGRAM_CHAT_ID

4. Скопируй адрес Worker, добавь `/reports` и передай его в `-ReportEndpoint` при сборке установщика.

Команда из папки проекта после развёртывания

       .\installer\Build-Release.ps1 -Repository 'applimenu/RadialMenu' -Version '1.2.4' -ReportEndpoint 'https://radialmenu-feedback.SUBDOMAIN.workers.dev/reports'

Worker обрабатывает сообщения длиной до 1200 символов. Лимиты отправки применяются по IP и на весь маршрут отдельно в каждой локации Cloudflare. Адрес чата и токен задаются через секреты Worker.

### Развёртывание ASP.NET Core

1. Создай бота через [@BotFather](https://t.me/BotFather) командой /newbot. Открой чат с новым ботом под своим аккаунтом и нажми Start.
2. Узнай числовой chat_id своего чата из результата Telegram Bot API getUpdates, пока у бота нет вебхука. Используй токен только в локальном терминале или секретах хостинга. Не публикуй его в GitHub и не передавай в сборку RadialMenu.
3. Опубликуй relay/RadialMenu.ReportRelay.csproj на хостинге ASP.NET Core с HTTPS. Установи серверные переменные Telegram__BotToken и Telegram__ChatId. Приложение будет отправлять введённый текст и номер своей версии в указанный чат через маршрут /reports. Успех показывается после подтверждения Telegram.
4. Собери установщик с адресом своего сервиса.

       .\installer\Build-Release.ps1 -Repository 'OWNER/REPO' -Version '1.0.0' -ReportEndpoint 'https://example.org/reports'

Если уже есть бот, который самостоятельно принимает сообщения, но отдельный HTTPS-сервис не нужен, вместо ReportEndpoint укажи -ReportBotUsername с именем бота без @. В сборке появится ссылка на бот без встроенной формы. Для сборки без адреса и без имени бота пункт «Сообщить об ошибке» скрыт.

Если отчёты должны приходить на почту, вместо Telegram можно подключить серверный почтовый API или SMTP. Серверу понадобится авторизованный отправитель и адрес получателя. У настольного приложения в таком варианте остаётся тот же HTTPS-маршрут и кнопка «Отправить».
